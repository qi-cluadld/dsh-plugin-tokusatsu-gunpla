## Что это такое

Помощник по идентификации, работающий внутри DeepSeek Harness и созданный ровно для двух задач:

- **Ремни Kamen Rider**: DX или CSM? Это KO?
- **Наборы Gunpla от Bandai**: EG / HG / RG / MG / PG / MB / Dissection Craft Machine — какой это грейд? Это подделка?

Одно правило дизайна действует на всём протяжении: **кроме шага «написать обзор», ничто не обращается к большой модели.** Фотоконтрольный список, распознавание, определение DX/CSM, обращения к базе знаний, оценка источников и фильтрация фейковых новостей — всё происходит на этой машине, при нулевом расходе токенов. Результаты попадают в локальный кэш, поэтому повторная идентификация той же партии фотографий ничего не пересчитывает.

> Этот плагин не является официальным инструментом. Идентификация носит справочный характер — см. [Отказ от ответственности](#отказ-от-ответственности).

## Что он умеет

### Обязательные требования к фотографиям (это ядро, а не подсказка)

Плагин **блокирует** запросы, в которых не хватает доказательств, вместо того чтобы выдать неточный ответ:

| Категория | Что обязательно сфотографировать | Когда нет коробки / невозможно выполнить |
|---|---|---|
| **Ремень** | Бакл **снят и сфотографирован отдельно**, спереди и сзади (на обратной стороне должна быть видна табличка с названием); устройство трансформации **снято и сфотографировано отдельно** | Добавьте ремень целиком, батарейный отсек, звук трансформации |
| **Gunpla** | **Лицевая сторона коробки** (с товарным знаком Bandai и цветовой полосой грейда) | Несколько ракурсов + характерные зоны + запись о покупке → если ничего из этого не помогает, **введите модель вручную** |
| Другое | Бренд, номер детали, крупный план таблички с названием | Несколько ракурсов |

Напоминание появляется в трёх местах, как и требует спецификация: **крупным текстом в стартовом руководстве**, **постоянный баннер в интерфейсе съёмки** (не только при ошибке) и **ещё раз, когда идентификация не удалась**.

### Логика различения DX / CSM

Оценка идёт в порядке **материал → размер → детали → вопрос о звуке**, и у каждого шага есть явные критерии:

- **Материал**: литые металлические детали, кожаная подкладка → сторона CSM
- **Размер**: на размер больше и толще, чем DX → сторона CSM
- **Детали**: лазерная гравировка, индивидуальные серийные номера, металлическая табличка → сторона CSM; литой товарный знак плюс год → сторона DX
- **Звук**: диалоги / BGM → в основном не DX; только звук трансформации и звук финишера → сторона DX

Когда две оценки оказываются близкими, плагин **не угадывает**: он возвращает «предположительно», перечисляет кандидатов, чтобы пользователь выбрал из них, и записывает выбор пользователя в **хранилище исправлений** (наивысший приоритет; последующие обновления никогда его не перезаписывают).

### Фейковые новости и оценка источников

Доверие к источнику **выводится**, а не проставляется:

```
Официальный сайт > официальный аккаунт X/YouTube (нужен VPN) > отечественный официальный аккаунт (синяя молния + подтверждённый субъект + аватар)
> официальный список релизов > официальный промо-ролик того года > крупный ритейлер / популярная вики
> посты и блоги того времени > создатель с жёлтой молнией > обычный создатель > групповой чат
```

**Распознавание аккаунтов Bilibili**: синяя молния = официальный; жёлтая молния = только для справки; без молнии = самый низкий уровень.
Синей молнии **недостаточно** — у аккаунта одновременно должны быть подтверждённый субъект, собственный аватар и заголовок **и** описание, отражающие тему игрушек или моделей. Если чего-то из этого не хватает, плагин **открывает диалог для подтверждения пользователем**, и подтверждение попадает в пользовательский белый список, чтобы больше не спрашивать.

**Правило входа**: как минимум **2 независимых источника** должны совпадать, и хотя бы 1 из них должен быть источником, пригодным для внесения в базу. Иначе запись помечается как «неподтверждённая». **Контент, созданный ИИ, предназначен только для отображения и никогда не вносится в базу.**

**Поисковые системы**: сначала китайский Bing; точка входа Baidu необязательна и при показе всегда помечается «непроверено»; Google для некитайских рынков, Yandex для русского; **360 / Sogou / 2345 никогда не используются**.

### Режим коллекционера (необязательно)

По умолчанию плагин охватывает только массовые позиции. При включении он также включает:

- **Gunpla**: PG / MGEX / MB / Dissection Craft Machine / RE100 / FULL MECHANICS / HI-RESOLUTION / лимитированные издания / зарубежные не-Bandai / GK
- **Ремни**: CSM / CS / игрушки из конфет / гасяпоны / лимитированные издания / малоизвестные аксессуары

### Многоязычность

Полная поддержка: **упрощённый китайский / традиционный китайский / английский / японский**.
Перевод интерфейса: корейский, французский, испанский, португальский, русский, кантонский, вьетнамский, немецкий, итальянский, нидерландский, польский.
Каждый язык откатывается к английскому, и отсутствующий ключ никогда не показывает сырой ключ.

## Установка

### Вариант 1: отправить ссылку на репозиторий прямо в DSH (рекомендуется)

```
Install this plugin for me: https://github.com/qi-cluadld/dsh-plugin-tokusatsu-gunpla/tree/main/dsh-plugin-tokusatsu-gunpla
```

DSH устанавливает его в профиль через `install_bundle` в `plugin_manager`. Это **единственный поддерживаемый** путь установки.

### Вариант 2: клонировать, а затем дать DSH установить из локального каталога

```bash
git clone https://github.com/qi-cluadld/dsh-plugin-tokusatsu-gunpla
cd dsh-plugin-tokusatsu-gunpla/dsh-plugin-tokusatsu-gunpla
```

Затем передайте **абсолютный путь этого каталога** в `plugin_manager`:

```
Use plugin_manager, action install_bundle, and set target to this directory's absolute path
```

### Не устанавливайте вручную

Следующие способы выглядят работающими, но заставляют плагин исчезнуть:

- создание символической ссылки внутри `node_modules` профиля (junction в Windows)
- ручная запись строки в `cordis.patch.yml` профиля
- копирование пакета в `$DSH_HOME`

Две причины, и обе плохо диагностируются самостоятельно:

1. **Разрешение зависимостей не удаётся.** Загрузчик разрешает пакет по его РЕАЛЬНОМУ пути (символические ссылки разыменовываются), поэтому Node ищет `node_modules` вверх от вашего рабочего пространства, где пакетов DSH нет. Добавить несколько недостаточно: сам `@deepseek-ai/dsh-tools` импортирует `dsh-scope`, `dsh-sandbox`, `dsh-llm` и другие, которые **отсутствуют в его собственном package.json**, поэтому нужно всё дерево.
2. **Загрузчик запоминает сбой.** Когда строка не активируется, загрузчик сохраняет `disabled: true` обратно в профиль, и каждый следующий запуск полностью её пропускает.

Оба сбоя проявляются одинаково: **ни интерфейса, ни инструментов**, без записи в журнале. О том, как их различить, см. [docs/INSTALL.md](docs/INSTALL.md).

Подробности см. в [docs/INSTALL.md](docs/INSTALL.md).

## Конфигурация

Всё меняется в `cordis.patch.yml` профиля:

| Поле | По умолчанию | Описание |
|---|---|---|
| `richMode` | `false` | Режим коллекционера |
| `visionEnabled` | `true` | Использовать ли локальную конечную точку зрения |
| `visionBaseUrl` | `''` | Совместимая с OpenAI конечная точка; оставьте пустой для автоподбора `127.0.0.1:11434 / :1234 / :8080` |
| `visionModel` | `''` | Имя модели; оставьте пустым, чтобы использовать первую, которую сообщит конечная точка |
| `visionTimeoutMs` | `120000` | Тайм-аут локального вывода |
| `visionMaxImages` | `6` | Ограничение числа изображений для одной идентификации |
| `cacheTtlMs` | `86400000` | Время жизни кэша идентификации, 0 отключает его |
| `searchLanguage` | `'zh'` | Язык поискового рынка |
| `allowBaidu` | `false` | Предлагать ли точку входа Baidu (всегда помечается «непроверено») |
| `showCompliance` | `false` | Показывать ли примечания GDPR / EU AI Act |
| `requireAcknowledgement` | `true` | Требуется ли сначала принять отказ от ответственности |

### О «распознавании локальной малой моделью»

Плагин **никогда** не загружает ваши фотографии в облако. Он обращается к совместимой с OpenAI конечной точке зрения, которая **уже работает на вашей собственной машине**:

```bash
# Пример: Ollama
ollama pull qwen2.5-vl
ollama serve        # слушает на 127.0.0.1:11434
```

Когда конечная точка недоступна, он не выдаёт ошибку и не обращается наружу — он автоматически деградирует до пути **фотоконтрольный список + ручной ввод модели**, по-прежнему при нулевом расходе токенов.

## Четыре локальных инструмента

После установки плагина помощник может использовать эти четыре инструмента. Они **все выполняются локально**:

| Инструмент | Назначение |
|---|---|
| `gear_identify` | Идентификация + вердикт о подделке + определение издания + уверенность; результат кэшируется и публикуется в UI |
| `gear_checklist` | Создание и проверка фотоконтрольного списка, вычисление того, чего ещё не хватает |
| `gear_decide_edition` | Оценка DX / CSM и цепочка уточняющих вопросов |
| `gear_knowledge` | Обращение к базе знаний, план поиска, оценка источников, перекрёстная проверка, записи в хранилище исправлений, записи в локальное хранилище |

Возвращаемые значения инструментов уже несут вывод и цепочку доказательств, поэтому помощнику **не нужно** снова угадывать модель — это также ключ к экономии токенов.

## Интерфейс

Три поверхности UI, все зарегистрированы через систему слотов Harness:

1. **Стартовое руководство** (`conversation.input.dock`, над полем ввода в разговоре): требования к фотографиям крупным текстом + флажок отказа от ответственности + примечания о соответствии + переключатель расширенного режима. **Интерфейс съёмки не появляется, пока не отмечено согласие.**
2. **Руководство по съёмке** (`conversation.composer.dock`, постоянное): переключатель категории, постоянный баннер-напоминание, отмечаемый фотоконтрольный список, живые подсказки о том, чего ещё не хватает.
3. **Панель результатов + страница настроек** (`settings.section`): карточки результатов несут уверенность и доказательства, а в спорных случаях можно выбрать исправление; страница настроек управляет языком, расширенным режимом, точкой входа Baidu, локальной конечной точкой, отказом от ответственности и примечаниями о соответствии.

## Разработка

```bash
node scripts/smoke.mjs         # 69 проверок: фотоконтрольный список, дерево решений, вердикт о подделке, оценка источников, сквозной прогон
node scripts/client-test.mjs   # 43 проверки: клиентский контракт, рендеринг на четырёх языках, регистрация слотов, откат i18n
```

Ни одному из тестов не нужны сеть или модель.

```
lib/
  index.js      точка входа плагина, схема конфигурации, проекция сессии (результаты в UI)
  tools.js      четыре инструмента, видимые модели
  identify.js   основной поток идентификации (доказательства → фильтр подделок → сопоставление → суждение → уверенность)
  checklist.js  движок требований к фотографиям
  decide.js     дерево решений DX/CSM
  sources.js    оценка источников, вердикты Bilibili, перекрёстная проверка, маршрутизация поисковых систем
  vision.js     клиент локальной конечной точки зрения + деградация
  store.js      трёхуровневая база знаний (встроенный seed / проверенное / пользовательские исправления)
  i18n.js       каталог языков, отказ от ответственности, примечания о соответствии
  client.js     браузерная половина (стартовое руководство / руководство по съёмке / панель результатов / страница настроек)
data/
  seed-catalog.json       встроенные записи и критерии
  official-whitelist.json официальный белый список подтверждённых субъектов
```

Локальный каталог данных: `$DSH_HOME/plugin-data/tokusatsu-gunpla/`. Удаление его — это способ реализовать ваше право на стирание.
