## 무엇인가요

DeepSeek Harness 안에서 실행되는 식별 도우미로, 정확히 두 가지 작업을 위해 만들었습니다:

- **가면라이더 벨트**: DX인가 CSM인가? KO인가?
- **반다이 건프라 키트**: EG / HG / RG / MG / PG / MB / Dissection Craft Machine — 어느 등급인가? 짝퉁인가?

설계 원칙 하나가 처음부터 끝까지 유지됩니다: **"리뷰 작성" 단계를 빼면 아무것도 대형 모델을 호출하지 않습니다.** 사진 체크리스트, 인식, DX/CSM 판정, 지식베이스 조회, 출처 등급 판정, 가짜 뉴스 필터링은 모두 이 컴퓨터에서 토큰 0으로 처리됩니다. 결과는 로컬 캐시에 들어가므로 같은 사진 묶음을 다시 식별해도 아무것도 다시 계산하지 않습니다.

> 이 플러그인은 공식 도구가 아닙니다. 식별은 참고용입니다 — [면책 조항](#면책-조항)을 보십시오.

## 할 수 있는 일

### 필수 사진 요구 사항 (힌트가 아니라 핵심입니다)

플러그인은 부정확한 답을 내놓는 대신 근거가 없는 요청을 **차단**합니다:

| 분류 | 반드시 촬영 | 박스가 없거나 촬영할 수 없을 때 |
|---|---|---|
| **벨트** | 버클 **분리 촬영**, 정면과 후면 (후면에는 명판이 보여야 합니다); 변신 기기 **분리 촬영** | 벨트 전체, 배터리실, 변신음 추가 |
| **건프라** | **박스 정면** (반다이 상표와 등급 색 띠 포함) | 여러 각도 + 특징 부위 + 구매 기록 → 그래도 안 되면 **모델명 직접 입력** |
| 기타 | 브랜드, 부품 번호, 명판 클로즈업 | 여러 각도 |

이 알림은 명세에 맞춰 세 곳에 나타납니다: **시작 안내의 큰 글씨**, **촬영 인터페이스의 상시 배너**(실패 시에만이 아님), 그리고 **식별에 실패했을 때 한 번 더**.

### DX / CSM 판별 로직

채점은 **재질 → 크기 → 디테일 → 소리 질문** 순서로 진행되고, 각 단계에 명시적 기준이 있습니다:

- **재질**: 다이캐스트 금속 부품, 가죽 안감 → CSM 쪽
- **크기**: DX보다 한 사이즈 크고 두껍습니다 → CSM 쪽
- **디테일**: 레이저 각인, 개별 일련번호, 금속 명판 → CSM 쪽; 사출 성형 상표와 연도 → DX 쪽
- **소리**: 대사 / BGM → 기본적으로 DX가 아님; 변신음과 필살기음만 → DX 쪽

두 점수가 비슷하게 나오면 플러그인은 **추측하지 않습니다**: "의심"으로 반환하고 사용자가 고를 후보를 나열하며, 사용자의 선택을 **정정 저장소**(최우선순위, 이후 업데이트가 절대 덮어쓰지 않음)에 기록합니다.

### 가짜 뉴스와 출처 등급

출처 신뢰도는 찍혀 있는 것이 아니라 **도출**됩니다:

```
공식 사이트 > X/YouTube 공식 계정 (VPN 필요) > 국내 공식 계정 (파란 번개 + 인증 주체 + 아바타)
> 공식 발매 목록 > 해당 연도 공식 홍보 영상 > 대형 유통사 / 주요 위키
> 당시 게시물/블로그 > 노란 번개 크리에이터 > 일반 크리에이터 > 단체 채팅방
```

**Bilibili 계정 인식**: 파란 번개 = 공식; 노란 번개 = 참고용; 번개 없음 = 최하.
파란 번개만으로는 **충분하지 않습니다** — 계정에 인증 주체, 직접 만든 아바타, 그리고 제목 **과** 설명이 모두 장난감/모형 테마를 반영해야 합니다. 이 중 하나라도 빠지면 플러그인은 **사용자에게 확인 대화상자를 열고**, 그 확인은 사용자 화이트리스트에 들어가 다시는 묻지 않습니다.

**유입 규칙**: 최소 **2개의 독립 출처**가 일치해야 하고, 그중 최소 1개는 등재 가능한 출처여야 합니다. 그렇지 않으면 그 항목은 "미확인"으로 표시됩니다. **AI 생성 콘텐츠는 표시 전용이며 절대 등재되지 않습니다.** AI 생성 콘텐츠는 표시만 되고 절대 등록되지 않습니다.

**검색 엔진**: 중국어권은 Bing 우선; Baidu 진입점은 선택 사항이고 표시될 때 항상 "미검증"으로 라벨이 붙습니다; 비중국어 시장은 Google, 러시아어는 Yandex; **360 / Sogou / 2345는 절대 사용하지 않습니다**.

### 리치 모드 (선택)

기본적으로 플러그인은 주류 제품만 다룹니다. 활성화하면 다음도 포함됩니다:

- **건프라**: PG / MGEX / MB / Dissection Craft Machine / RE100 / FULL MECHANICS / HI-RESOLUTION / 한정판 / 해외 비반다이 / GK
- **벨트**: CSM / CS / 캔디토이 / 가샤폰 / 한정판 / 비주류 액세서리

### 다국어

완전 지원: **중국어 간체 / 중국어 번체 / 영어 / 일본어**.
UI 번역: 한국어, 프랑스어, 스페인어, 포르투갈어, 러시아어, 광둥어, 베트남어, 독일어, 이탈리아어, 네덜란드어, 폴란드어.
모든 언어는 영어로 폴백되며, 키가 빠져도 원시 키가 노출되는 일은 없습니다.

## 설치

### 옵션 1: 저장소 링크를 DSH에 그대로 보내기 (권장)

```
이 플러그인을 설치해 주세요: https://github.com/qi-cluadld/dsh-plugin-tokusatsu-gunpla/tree/main/dsh-plugin-tokusatsu-gunpla
```

DSH는 `plugin_manager`의 `install_bundle`을 통해 프로필에 설치합니다. 이것이 **유일하게 지원되는** 설치 경로입니다.

### 옵션 2: 클론한 뒤 DSH가 로컬 디렉터리에서 설치하게 하기

```bash
git clone https://github.com/qi-cluadld/dsh-plugin-tokusatsu-gunpla
cd dsh-plugin-tokusatsu-gunpla/dsh-plugin-tokusatsu-gunpla
```

그런 다음 **그 디렉터리의 절대 경로**를 `plugin_manager`에 넘기십시오:

```
plugin_manager를 사용하고 action은 install_bundle, target은 이 디렉터리의 절대 경로로 설정하십시오
```

### 직접 설치하지 마십시오

다음 방법들은 작동하는 것처럼 보이지만 플러그인을 사라지게 만듭니다:

- 프로필의 `node_modules` 안에 심볼릭 링크 만들기 (Windows에서는 정션)
- 프로필의 `cordis.patch.yml`에 한 줄을 직접 적어 넣기
- `$DSH_HOME` 아래에 패키지 복사하기

이유는 두 가지이고, 둘 다 스스로 진단하기 어렵습니다:

1. **의존성 해석이 실패합니다.** 로더는 패키지를 실제 경로로 해석하므로(심볼릭 링크는 해제됩니다), Node는 워크스페이스에서 위로 올라가며 `node_modules`를 찾지만 DSH 패키지들은 거기에 없습니다. 몇 개를 패치해 넣어도 충분하지 않습니다: `@deepseek-ai/dsh-tools` 자체가 `dsh-scope`, `dsh-sandbox`, `dsh-llm` 등을 import하는데 이것들은 **자기 package.json에 없으므로**, 트리 전체가 필요합니다.
2. **로더는 실패를 기억합니다.** 어떤 행이 활성화에 실패하면 로더는 `disabled: true`를 프로필에 기록하고, 이후 모든 시작에서 그 행을 완전히 건너뜁니다.

둘 다 똑같이 나타납니다: **인터페이스도 도구도 없음**, 로그도 없음. 둘을 구별하는 방법은 [docs/INSTALL.md](docs/INSTALL.md)를 보십시오.

자세한 내용은 [docs/INSTALL.md](docs/INSTALL.md)를 보십시오.

## 설정

모든 것은 프로필의 `cordis.patch.yml`에서 바꿉니다:

| 필드 | 기본값 | 설명 |
|---|---|---|
| `richMode` | `false` | 리치 모드 |
| `visionEnabled` | `true` | 로컬 비전 엔드포인트를 사용할지 여부 |
| `visionBaseUrl` | `''` | OpenAI 호환 엔드포인트; 비워 두면 `127.0.0.1:11434 / :1234 / :8080`을 자동 탐색 |
| `visionModel` | `''` | 모델 이름; 비워 두면 엔드포인트가 보고하는 첫 번째 모델 사용 |
| `visionTimeoutMs` | `120000` | 로컬 추론 타임아웃 |
| `visionMaxImages` | `6` | 한 번의 식별에 쓰는 이미지 상한 |
| `cacheTtlMs` | `86400000` | 식별 캐시 수명, 0이면 비활성 |
| `searchLanguage` | `'zh'` | 검색 시장 언어 |
| `allowBaidu` | `false` | Baidu 진입점을 제공할지 여부 (항상 "미검증"으로 라벨이 붙음) |
| `showCompliance` | `false` | GDPR / EU AI Act 고지를 표시할지 여부 |
| `requireAcknowledgement` | `true` | 면책 조항을 먼저 수락해야 하는지 여부 |

### "로컬 소형 모델 인식"에 대하여

플러그인은 사진을 클라우드에 **절대** 업로드하지 않습니다. **이미 내 컴퓨터에서 돌고 있는** OpenAI 호환 비전 엔드포인트를 호출합니다:

```bash
# 예: Ollama
ollama pull qwen2.5-vl
ollama serve        # 127.0.0.1:11434에서 수신
```

엔드포인트를 쓸 수 없을 때도 오류를 내거나 바깥으로 호출하지 않고, 자동으로 **사진 체크리스트 + 모델명 직접 입력** 경로로 저하되며 여전히 토큰은 0입니다.

## 네 가지 로컬 도구

플러그인을 설치하면 어시스턴트가 이 네 가지 도구를 쓸 수 있습니다. **모두 로컬에서 실행됩니다**:

| 도구 | 목적 |
|---|---|
| `gear_identify` | 식별 + 짝퉁 판정 + 에디션 판단 + 신뢰도; 결과는 캐시되어 UI에 게시됩니다 |
| `gear_checklist` | 사진 체크리스트 생성/점검, 아직 빠진 항목 산출 |
| `gear_decide_edition` | DX / CSM 채점과 후속 질문 체인 |
| `gear_knowledge` | 지식베이스 조회, 검색 계획, 출처 채점, 교차 검증, 정정 저장소 쓰기, 로컬 저장소 쓰기 |

도구 반환값에는 이미 결론과 근거 체인이 들어 있으므로 어시스턴트가 모델을 다시 추측할 **필요가 없습니다** — 이것이 토큰을 아끼는 핵심이기도 합니다.

## 인터페이스

세 개의 UI 표면이 있고, 모두 Harness 슬롯 시스템(`conversation.input.dock`, `conversation.composer.dock`, `settings.section`)으로 등록됩니다:

1. **시작 안내** (대화 입력 영역 위): 큰 글씨 사진 요구 사항 + 면책 조항 체크박스 + 컴플라이언스 고지 + 리치 모드 토글. **동의를 체크하기 전에는 촬영 인터페이스가 나타나지 않습니다.**
2. **촬영 안내** (상시): 카테고리 전환, 상시 알림 배너, 체크할 수 있는 사진 체크리스트, 아직 빠진 항목에 대한 실시간 힌트.
3. **결과 패널 + 설정 페이지**: 결과 카드에 신뢰도와 근거가 실리고, 의심 사례에서는 정정을 골라 넣을 수 있습니다; 설정 페이지에서는 언어, 리치 모드, Baidu 진입점, 로컬 엔드포인트, 면책 조항, 컴플라이언스 고지를 관리합니다.

## 개발

```bash
node scripts/smoke.mjs         # 69개 검사: 사진 체크리스트, 결정 트리, 짝퉁 판정, 출처 등급, 엔드투엔드
node scripts/client-test.mjs   # 43개 검사: 클라이언트 계약, 4개 언어 렌더링, 슬롯 등록, i18n 폴백
```

두 테스트 모두 네트워크나 모델이 필요하지 않습니다.

```
lib/
  index.js      플러그인 진입점, 설정 스키마, 세션 프로젝션 (결과를 UI로)
  tools.js      모델에 노출되는 네 가지 도구
  identify.js   주 식별 흐름 (근거 → 짝퉁 게이트 → 매칭 → 판단 → 신뢰도)
  checklist.js  사진 요구 사항 엔진
  decide.js     DX/CSM 결정 트리
  sources.js    출처 등급, Bilibili 판정, 교차 검증, 검색 엔진 라우팅
  vision.js     로컬 비전 엔드포인트 클라이언트 + 저하 처리
  store.js      3계층 지식베이스 (내장 시드 / 검증됨 / 사용자 정정)
  i18n.js       언어 카탈로그, 면책 조항, 컴플라이언스 고지
  client.js     브라우저 쪽 (시작 안내 / 촬영 안내 / 결과 패널 / 설정 페이지)
data/
  seed-catalog.json       내장 항목과 기준
  official-whitelist.json 공식 인증 주체 화이트리스트
```

로컬 데이터 디렉터리: `$DSH_HOME/plugin-data/tokusatsu-gunpla/`. 이 디렉터리를 지우는 것이 삭제권을 행사하는 방법입니다.

## 면책 조항

시작 안내(체크박스 뒤), 이 README, 설정 페이지 — 세 곳에 배치됩니다:

1. **식별 결과는 참고용입니다**: 이 플러그인은 공식 도구가 아니며 결과에 오류가 있을 수 있습니다.
2. **비공식**: 반다이, 도에이, 츠부라야 및 어떤 제조사와도 관계가 없으며, 허가나 보증을 받지 않았습니다.
3. **데이터는 공개 자료에서 옵니다**: 공개 자료를 정리한 것이므로 오래되었거나 부정확할 수 있으며, 공식 정보를 우선하십시오.
