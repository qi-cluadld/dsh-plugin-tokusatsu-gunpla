# 0.1.1 补丁说明：一次由依赖声明引起的宿主故障

**发布时间**：2026-10-23
**影响版本**：0.1.0（npm 上仍可下载，**请勿安装**）
**修复版本**：0.1.1

---

## 一句话

0.1.0 的 `package.json` 把 DSH 宿主自带的四个包写进了 `dependencies`。安装时 pnpm 会据此重排整个 profile 的依赖树，把宿主正在用的包一起换掉，于是 DSH 当场出问题。0.1.1 删掉了那四行，只留下 `peerDependencies`。

## 到底发生了什么

| 项 | 0.1.0 | 0.1.1 |
|---|---|---|
| `dependencies` | `cordis`、`dsh-tools`、`schemastery`、`dsh-session-projection`、`zod` | 只剩 `zod` |
| `peerDependencies` | 前三个（session-projection 为可选 peer） | 不变 |
| 安装时对 profile 的影响 | **重排依赖树**，实测 `Packages: +8 -10`，并出现 peer 冲突警告 | 只添加插件本身 |
| 结果 | 宿主依赖被替换，功能异常 | 插件自身运行，不触碰宿主 |

`cordis`、`dsh-tools`、`schemastery` 这些包**由 DSH 提供**，插件只能声明「我需要它们」，不能「自带一份」。一旦自带，同一个运行时会被加载两遍，再加上 pnpm 的 hoisted 策略会把它们提升到 profile 根目录、和别的插件一起重新解析，宿主的依赖集合就被改写了。

发生故障时，插件管理器的日志里能看到这一行：

```
[WARN] Issues with peer dependencies found.
Packages: +8 -10
+ dsh-plugin-tokusatsu-gunpla 0.1.0
```

**装一个插件，动了 10 个别的包**——这就是问题本身。

## 没有发生的事（这点很重要）

- **没有上传任何照片、识别结果或本地知识库**。这是一次本地依赖解析错误，不是隐私事故，不涉及你的纠正记录。
- **没有改动你的 DSH 数据目录**。会话、插件数据、凭据都不在这次故障的路径上。

## 谁受影响

- **没装过 0.1.0**：不受影响，也不必升级（升了也没有坏处）。
- **装过 0.1.0**：请在 **设置 → 插件** 里卸载它，然后重启一次 DSH，让 profile 重新建立。不要手工删 `~/.dsh` —— 那会把会话记录一起清掉。

## 我们错在哪

1. **依赖声明写错了，而且错得很基础。** 宿主提供的包必须只出现在 `peerDependencies`，这是插件开发的第一课。0.1.0 里四个包同时出现在 `dependencies`，`peerDependenciesMeta` 又把其中一个标成「可选 peer」，自相矛盾。
2. **自检的方式，恰好绕开了这个错误。** 发布前的验证是「装进一个空的消费者项目，四套测试通过」。可那个环境里，npm 会把插件的依赖装成整棵树里**唯一的一份**——双运行时在那里不可能出现。我们测的是「tarball 自洽」，不是「能和宿主共存」，却把它当成了后者。
3. **文档和做法互相打架。** `docs/INSTALL.md` 写着「不要手工装」，仓库里却附了一个专门做手工装的 `scripts/install-deps.mjs`。一个禁止某做法的文档，配一个实现该做法的脚本，比没有文档更糟。

三条都是我们的问题，没有一条能推给环境。

## 怎么升级

```bash
npm install dsh-plugin-tokusatsu-gunpla@0.1.1
```

或者在 DSH 的 **设置 → 插件** 里更新。

装完可以自己验证有没有变干净：插件管理器的日志里应当**只有**这一行新增，没有任何 `-` 开头的包：

```
+ dsh-plugin-tokusatsu-gunpla 0.1.1
```

## 出了问题怎么回退

**设置 → 插件 → 卸载**，然后重启 DSH。这是唯一被支持的卸载方式；手工删 profile 里的 `node_modules` 会把别的插件一起带走。

## 以后怎么防止再犯

- `dependencies` 里只允许出现宿主不提供的包；这条会由发布前检查拦住，不再靠人记。
- 安装验证以「在真实 profile 里只解析到一份宿主运行时」为标准，不再以空项目通过为标准。
- 文档只描述被支持的做法；实现不了支持路径的脚本，删除而不是保留。

## 对不住

B 站那边几千个人等着用，我们在第一个公开版本上就交了这个学费，还让你们替我们承担了排查成本。这次的错误是可以避免的，是我们没做够。

有问题直接开 issue：<https://github.com/qi-cluadld/dsh-plugin-tokusatsu-gunpla/issues>
